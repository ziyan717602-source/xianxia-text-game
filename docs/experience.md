# 开发经验记录

更新时间：2026-05-08

这份文档用于持续记录本项目和其他游戏/程序开发可复用的方法、工具、提示词和踩坑。每次完成阶段性工作后更新。

## 已验证经验

- 先写项目级 agent 指令，再让 AI 开发游戏代码。这样能减少版权、架构和测试方向漂移。
- 2026-05-07：`AGENTS.md` 应是地图而非手册。只放项目全貌、硬规则、命令矩阵、目录导航和验证闭环；详细设计、素材、复盘和模块细节放 `docs/`，项目 skill 只做触发后的薄入口。
- 对文字增量游戏，核心逻辑必须可测试；UI 截图无法证明资源循环正确。
- 修仙题材适合把“资源增长”包装成“修行代价”：丹毒、心魔、因果、天劫比单纯货币更有辨识度。
- 远程仓库建立前也应先初始化本地 git，并在文档里记录云端步骤，避免早期文件散落。
- 未审计的第三方 skills 不直接安装。优先官方 curated skills；项目特化能力用本地 skill 自建。
- 道途不要开局锁死。用行为统计和事件后果自然形成路线，玩家才会觉得“这是我修出来的路”。
- 旧动作要自动化或升格。玩家重复十几次后，系统应提供日课、批量、闭关、阵法或托管，而不是继续要求机械点击。
- 鲜活世界来自状态变化和关系痕迹，不来自堆长剧情。季节、物价、NPC 去留、旧债和机缘过期都能制造世界感。
- 文字选择要进入状态账本。少量会被后续读取的 flag/tag/quality，比大量无后果分支更有价值。
- 仙侠感不能只靠境界名。寿元、灵根、五行相性、丹药药性、地点灵气、宗门规矩和天劫都要逐步进入系统。
- 斗法可以低占比，但不能完全空缺；适合先作为巡山/秘境/宗门争端里的风险事件。
- 2026-05-07：PC 开发已建立原型骨架，但 README/PLAN 容易过期；每次阶段推进后必须同步 `README.md`、`PLAN.md`、`docs/project-status.md`。
- 2026-05-07：地点模型只建在逻辑层不等于玩家能感知；UI 必须接入地点行动过滤和地点切换，否则世界仍像按钮列表。
- 2026-05-07：事件 flag 不等于关系记忆；涉及 NPC 的事件应写入关系账本。
- 2026-05-07：反坐牢机制不要只写 unlock flag；一旦出现 `unlocked_rike_tuna`，就应有对应的日课/批量行动和测试。
- 2026-05-07：没有 Playwright 依赖时，也可以用本机 Chromium/Edge 的 DevTools Protocol 做轻量烟测，但脚本必须负责清理浏览器进程树。
- 2026-05-07：地点账本不应只是地点名和按钮列表；事件抽取也要读取地点权重，否则“山路危险、坊市多传闻”不会进入真实结算。
- 2026-05-07：内容资料要提前机制化。节气、地点、NPC、灵根、五行、草药等素材进入 `docs/content-bank/` 时，必须带条件、权重、状态后果或系统轴，避免后续开发时只剩散乱设定。
- 2026-05-07：世界鲜活感要进入存档状态。把节气日志、十日摘要和近期行动统计放进 `GameState.world`，比只在 React 日志里拼文字更容易测试、迁移和跨设备延续。
- 2026-05-07：数值初调要变成测试约束。阶段 1C 用“约 19 次成功行动、185 个游戏 tick、10 次手动吐纳后必须日课”的路线测试，防止后续改动把早期体验重新调回纯点击或跳过日课。
- 2026-05-07：行动按钮不能只看 `unlockedActions`。UI 可见行动还必须读 required flag、required realm 和地点条件，否则一次性突破动作会在完成后继续显示。
- 2026-05-07：普通出身应是起始接触面，不是职业锁。用 tags/qualities、起始地点和少量行动开放来表达差异；旧存档迁移成“旧途”，避免破坏已有进度。
- 2026-05-07：灵根不应开局选择。先作为隐藏修行账本随 seed 生成，炼气后通过行动揭示，再让功法相性影响收益；这样能保留“不是职业锁”的设计，同时让五行进入真实结算。
- 2026-05-07：丹药第一版要先把“药性”和“代价”建进数据，而不是只做加真气按钮。小聚气丸用配方、药性、成功率、服丹丹毒和调息惩罚形成闭环，后续丹方可以复用同一结构。
- 2026-05-07：突破不要直接做成“升级”按钮。先用稳固关口建立准备状态，再让冲关读取相性、清修、伤势和丹毒；失败要留下账本后果，半成则转化成下一次的稳定度。
- 2026-05-07：冲关配套丹药应提供取舍，不只加成功率。稳息散用“降少量丹毒、损一点真气、护下一次冲关”形成稳冲路线，和小聚气丸的快冲路线区分开。
- 2026-05-07：解毒不应只是撤销惩罚。清躁丸用“退丹毒/伤势/冒进，但损精元”做成取舍；丹毒入脉先触发事件，让高丹毒成为可见局面，而不是只在面板上变成更高数字。
- 2026-05-08：重复积累升格应复用既有账本。三日闭关不新增资源，只用更长 cooldown、更高精元成本和 `quiet_cultivation` 记录，把日课升级成批量行动；外门供给也先用 `sect_trace` 和短差次数解锁，避免过早设计完整宗门经济。
- 2026-05-08：浏览器烟测要处理随机事件弹窗。行动后如果事件出现，地点和行动按钮会被禁用；烟测脚本应先收束事件再继续断言，避免把随机触发误判为地点切换回归。

## 推荐提示词模板

### 实现玩法前

```text
请先阅读 AGENTS.md、docs/design-direction.md、docs/game-design.md、docs/experience.md。
我要实现 [系统名]。先给出资源流、解锁条件、失败/代价、测试点，再修改代码。
不要使用任何现有仙侠 IP 的专有名称或剧情。
```

### 数值调优

```text
请检查 [资源/系统] 的前 10 分钟节奏。
目标是 [更快解锁/减少等待/增加选择压力]。
输出需要包含：调整原因、改动文件、验证方法、可能副作用。
```

### Bug 修复

```text
请复现并修复这个问题：[现象]。
先定位是否属于状态模拟、存档迁移、UI 渲染或事件触发。
修复后运行相关测试，并说明未覆盖风险。
```

## 工具记录

- Codex：适合整体规划、文件编辑、测试和仓库维护。
- Playwright / browser testing：适合验证本地 Web 游戏是否能点击、存档、刷新恢复。
- GitHub/Cursor/Claude Code：通过仓库指令文件保持一致行为。
- Web 调研：只把机制级经验写入仓库，避免搬运受版权保护的文本和设定。
- Node.js：WindowsApps 中 Codex 自带的 `node.exe` 可能被系统权限拦截；已安装官方 Node.js LTS 到 `C:\Program Files\nodejs`，当前会话必要时把该路径临时前置到 PATH。
