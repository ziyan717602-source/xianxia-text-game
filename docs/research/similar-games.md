# 同类游戏调研

更新时间：2026-05-06

## 可借鉴方向

### A Dark Room

来源：[A Dark Room GitHub](https://github.com/doublespeakgames/adarkroom)，[网页版](https://adarkroom.doublespeakgames.com/)

- 从极少动作开始，系统逐步出现，玩家通过交互理解世界。
- 资源循环和叙事推进紧密耦合，按钮本身就是世界观的一部分。
- 早期等待和手动操作形成记忆点，但后续必须靠新系统持续加深。

对本项目的转化：开局只给“添柴、打坐、翻残卷”等少数动作；把境界、炼丹、秘境、宗门作为渐进解锁，而不是开场菜单。

### Kittens Game

来源：[Kittens Game GitHub](https://github.com/nuclear-unicorn/kittensgame)，[网页版](https://kittensgame.com/web/)

- 大量资源、建筑、科技和重置层构成长线可玩性。
- 复杂系统适合后期，但早期要控制认知负担。

对本项目的转化：中后期可加入洞府、灵田、弟子、宗门贡献、阵法、飞升重置，但每次只开放少量新概念。

### Candy Box / Candy Box 2

来源：[Candy Box 2 GitHub](https://github.com/candybox2/candybox2.github.io)，[Candy Box 2](https://candybox2.github.io/)

- 文本和 ASCII 风格可以承载惊喜、探索与幽默。
- 从单一资源逐步变成冒险、装备和任务。

对本项目的转化：可以保留“文字即道具”的味道，例如残卷、石碑、符箓、卦象等可点击文本。

### Universal Paperclips

来源：[Universal Paperclips](https://www.decisionproblem.com/paperclips/)

- 单一目标不断外延，最后扩展到远超开局想象的规模。
- 数值膨胀背后有明确叙事方向。

对本项目的转化：从“活下去并感知灵气”逐渐扩展到“处理因果、天劫、飞升代价”，避免只做资源表格。

### Crank / Armory & Machine 类极简增量游戏

- 早期通过少数按钮和短文案制造未知感。
- 适合参考“操作解锁操作”的节奏，而不是参考具体内容。

对本项目的转化：让“读残卷”解锁“吐纳”，“稳定炉火”解锁“炼丹”，“踏入山径”解锁“秘境”。

### 修仙与 MUD 方向

来源：[Muddery](https://www.muddery.org/)，[vue-XiuXianGame](https://github.com/setube/vue-XiuXianGame)

- MUD 和文字修仙天然重视地点、状态、门派、技能和长期成长。
- 现代浏览器实现可以保留文字交互，同时加入自动化和存档便利。

对本项目的转化：地点和事件可以像 MUD 一样组织，但操作密度应更接近增量游戏，减少纯命令输入门槛。

## 素材池

### 地点

寒舍、后山、溪谷、药圃、废观、坊市、外门、藏经阁、炼丹房、试炼峰、秘境裂隙、古战场、洞府、天门。

### 行动

添柴、打坐、吐纳、采药、辨药、炼丹、温炉、画符、布阵、巡山、闭关、问道、交易、结缘、斩念、渡劫。

### 事件种子

- 残卷在雨夜发热，字迹浮现。
- 山中药香异常，采药时遭遇受伤散修。
- 坊市出现来历不明的丹炉，价格低得反常。
- 突破前夜听见心魔问答，玩家可选择稳固、冒进或放弃。
- 宗门任务要求牺牲短期资源换取长期声望。

## 版权边界

- 不使用现有仙侠作品的人名、宗门名、剧情线、地图名、法宝名和专有术语组合。
- 可使用公共类型元素：境界、炼丹、符箓、阵法、天劫、灵石、洞府、门派等。
- 对同类游戏只借鉴机制结构，不复刻文案、界面布局、数值表或剧情。
